# Culinary Blog

Веб-приложение для публикации и управления кулинарным контентом. Проект написан на **C# и ASP.NET Core MVC**. Для хранения данных используется **Google Cloud Firestore**, а HTML-страницы формируются с помощью Razor Views.

## Возможности

- **Рецепты:** просмотр списка, просмотр подробностей, создание, редактирование и удаление рецептов.
- **Блоги:** создание и управление блогами.
- **Публикации:** создание, просмотр, редактирование и удаление постов, связанных с блогами.
- **Комментарии и оценки:** отдельные разделы для управления комментариями и рейтингами рецептов.
- **Форма регистрации:** сохранение имени, email, телефона, страны и даты рождения; проверка email на повторную регистрацию.
- **Кулинарные предпочтения:** анкета с уровнем кулинарных навыков, частотой готовки, предпочтениями в питании, интересами и кухонным оборудованием.
- **Тесты:** модульные тесты сервисного слоя и интеграционные тесты MVC-маршрутов и Razor Views.

## Данные в Firestore

Код использует следующие коллекции Firestore:

| Коллекция | Назначение |
| --- | --- |
| `recipes` | Рецепты |
| `blogs` | Блоги |
| `posts` | Публикации блогов |
| `comments` | Комментарии к публикациям |
| `ratings` | Оценки рецептов |
| `registrations` | Данные регистрационной формы |
| `cooking_preferences` | Кулинарные предпочтения пользователей |

При первом запуске убедитесь, что соответствующий проект Firebase создан, а Firestore Database включена.

## Настройка и запуск

1. Клонируйте репозиторий и перейдите в каталог проекта:

   ```bash
   git clone <URL-репозитория>
   cd Project001
   ```

2. Откройте проект и восстановите зависимости:

   ```bash
   dotnet restore
   ```

3. В `appsettings.json` задайте параметры Firebase:

   ```json
   {
     "Firebase": {
       "ProjectId": "YOUR_FIREBASE_PROJECT_ID",
       "CredentialsPath": "firebase-service-account.json"
     }
   }
   ```

   Сохраните настройки логирования и остальные существующие параметры файла. Вместо `YOUR_FIREBASE_PROJECT_ID` укажите ID своего проекта Firebase.

4. Создайте ключ сервисного аккаунта в Google Cloud Console и сохраните JSON-файл локально под именем, указанным в `CredentialsPath`. **Не добавляйте этот файл в Git и не публикуйте его содержимое.**

   В текущем `Program.cs` путь к учётным данным формируется относительно `AppContext.BaseDirectory` — каталога сборки приложения. Убедитесь, что JSON-файл доступен по получившемуся пути. В качестве альтернативы можно изменить код, чтобы путь строился относительно `builder.Environment.ContentRootPath`.

5. Запустите приложение:

   ```bash
   dotnet run --project Project001.csproj
   ```

   Откройте адрес HTTPS, который будет указан в выводе консоли.

## Запуск тестов

Из каталога решения выполните:

```bash
 dotnet test Project001.slnx
```

Либо запустите тестовый проект напрямую:

```bash
 dotnet test Project001.Tests/Project001.Tests.csproj
```

Модульные тесты подменяют репозитории с помощью Moq. Интеграционные тесты используют `WebApplicationFactory` и тестовый сервис, поэтому для этих тестов не требуется подключаться к настоящей базе Firestore.

## Безопасность

- Не коммитьте JSON-файлы сервисных аккаунтов, пароли, токены и другие секреты.
- Для локальных конфигураций с секретами используйте переменные окружения или .NET User Secrets.
- Перед развёртыванием проверьте права доступа к Firestore и защиту персональных данных, отправляемых через формы.

## Состояние проекта

Перед запуском проверьте `Program.cs`: в предоставленной версии файла присутствуют маркеры незавершённого Git merge (`<<<<<<<`, `=======`, `>>>>>>>`). Их нужно разрешить и оставить одну корректную реализацию, иначе проект не скомпилируется.
