# Валидация введённых данных — что сделано

Задача SCRUM: «Додати валідацію введених даних».

## 1. Разрешены конфликты слияния

В репозитории лежали четыре файла с маркерами `<<<<<<< HEAD` / `>>>>>>>`.
С ними проект не компилировался. Во всех случаях оставлена версия HEAD —
она новее и содержит регистрацию `IRegistrationStore`.

- `Program.cs`
- `Views/Shared/_Layout.cshtml`
- `Views/Home/Index.cshtml`
- `Views/Blogs/Index.cshtml`

## 2. Инфраструктура валидации

**`Views/_ViewImports.cshtml`** — новый файл. Его не было, поэтому во всём проекте
не работали tag helper'ы: `asp-for`, `asp-validation-for`, `asp-controller`,
`asp-action`. Форма регистрации из-за этого отправлялась не на тот адрес.

**`Views/Shared/_ValidationScriptsPartial.cshtml`** — был пустой заглушкой Razor Pages
(`@page` + PageModel). Переписан: подключает `jquery.validate` и
`jquery.validate.unobtrusive` из `wwwroot/lib`.

**`Views/Shared/_Layout.cshtml`** — добавлено подключение jQuery и этого partial,
чтобы клиентская валидация работала на всех страницах.

## 3. Валидация моделей

Атрибутов `DataAnnotations` в сущностях не было вообще — `ModelState.IsValid`
всегда возвращал `true`, и в базу можно было записать пустой рецепт.

| Модель | Правила |
| --- | --- |
| `Recipe` | Title 3–120, Description 10–500, Ingredients 5–2000, Instructions 10–5000 — все обязательны |
| `Blog` | Title 3–100, Description 10–500 — обязательны |
| `Post` | BlogId обязателен, Title 3–150, Content 10–10000 |
| `Comment` | PostId обязателен, Author 2–60, Content 2–1000 |
| `Rating` | RecipeId обязателен, UserId > 0, Value от 1 до 5 |

У всех полей проставлен `Display(Name)` — подписи в формах берутся из модели,
а не дублируются в разметке.

## 4. Формы

Контроллеры `RecipesController` и `BlogsController` вызывали представления
Create, Edit и Delete, которых не существовало — переход на них давал ошибку.
Созданы с полной разметкой валидации:

- `Views/Recipes/Create.cshtml`
- `Views/Recipes/Edit.cshtml`
- `Views/Recipes/Delete.cshtml`
- `Views/Blogs/Create.cshtml`
- `Views/Blogs/Edit.cshtml`

В каждой форме: `asp-validation-summary` для общих ошибок, `asp-validation-for`
под каждым полем, скрытые поля для идентификатора и даты создания.

## Как это работает — два уровня

**Клиентский.** Tag helper'ы генерируют `data-val` атрибуты из правил модели,
`jquery.validate.unobtrusive` их читает и проверяет форму до отправки.
Пользователь видит ошибку сразу, запрос на сервер не уходит.

**Серверный.** `ModelState.IsValid` в контроллере. Это обязательный рубеж:
клиентскую проверку можно обойти, отключив JavaScript или отправив запрос напрямую.
Поэтому проверка дублируется, и в базу некорректные данные не попадают в любом случае.

## Что осталось за рамками задачи

- `Views/Posts/*` — контроллер постов не проверялся, формы не трогал
- `Views/Blogs/Details.cshtml`, `Views/Blogs/Delete.cshtml` — контроллер их вызывает, но файлов нет
- Форма регистрации `Views/Form/Form.cshtml` выводит ошибки своим способом,
  через чтение `ModelState` вручную. Работает, переписывать не стал — после
  появления `_ViewImports` у неё починился адрес отправки, этого достаточно

## Проверка

1. Открыть `/Recipes/Create`, нажать «Сохранить» с пустыми полями —
   должны появиться сообщения под каждым полем, страница не перезагрузится.
2. Ввести название из двух букв — «Название: от 3 до 120 символов».
3. Отключить JavaScript в браузере и повторить — форма уйдёт на сервер,
   но вернётся с теми же ошибками и сохранёнными данными.

Третий пункт стоит показать на защите: он доказывает, что валидация не только
клиентская.
